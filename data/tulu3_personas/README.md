# Tulu-3 Personas Data Notes

This folder stores the local files we prepared for the Tulu-3 personas SFT experiments.

## Files

- `tulu3_personas_sft.jsonl`
  - The full local export of `allenai/tulu-3-sft-personas-instruction-following`.
  - Each line is one JSON object.
  - Main fields in each sample:
    - `id`
    - `prompt`
    - `messages`
    - `constraints`

- `tulu3_personas_sft_personalized.jsonl`
  - A filtered subset from the full SFT file.
  - It keeps samples whose prompts contain obvious persona/profile signals.
  - This subset is meant for a more focused personalization experiment.

- `tulu3_personas_sft_personalized_report.json`
  - A report generated by the filtering script.
  - It records:
    - how many samples were scanned
    - how many samples were kept
    - which matching rules were triggered
    - a small preview of matched samples

## Why There Are Two SFT Files

We currently keep both:

- the **full** SFT dataset
- the **persona-focused subset**

because they may support two different experiment settings:

1. `tulu3_personas_sft`
   - Use the full dataset as a general instruction-following SFT baseline.

2. `tulu3_personas_sft_personalized`
   - Use the filtered subset as a more focused persona-conditioned SFT dataset.

This is useful because the full dataset is not purely personalized. Some samples clearly contain persona or profile information, while others are mostly generic constrained instruction-following tasks.

## How These Files Are Produced

- Download script:
  - `scripts/personalization_data/download_tulu3_personas_sft.py`

- Filter script:
  - `scripts/personalization_data/filter_tulu3_personas_sft.py`

The filter script uses simple, explainable prompt rules such as:

- `As a ...`
- `As an ...`
- `I'm a ...`
- `my clients`
- `known for my`
- political identity phrases like `As a liberal ...`

So the filtered subset is a **rule-based first pass**, not a perfect gold-standard personalization dataset.

## How The Dataset Is Registered In dataset_info.json

We registered two dataset names in `data/dataset_info.json`:

- `tulu3_personas_sft`
- `tulu3_personas_sft_personalized`

Both use the same message-style schema.

### Meaning of the key fields

```json
"formatting": "sharegpt"
```

This tells LLaMAFactory to treat the data as a multi-message conversation format rather than `instruction/input/output` alpaca format.

```json
"columns": {
  "messages": "messages"
}
```

This means:

- LLaMAFactory expects a conversation/message-list field called `messages`
- our actual json/jsonl field is also called `messages`

So this is a field mapping declaration.

```json
"tags": {
  "role_tag": "role",
  "content_tag": "content",
  "user_tag": "user",
  "assistant_tag": "assistant"
}
```

This tells LLaMAFactory how to read each message object inside the `messages` list:

- the role field is named `role`
- the text field is named `content`
- user messages use role value `user`
- assistant messages use role value `assistant`

## Important Practical Note

In this dataset:

- `prompt` and `messages[0].content` are duplicated
- the actual training conversation is already fully represented in `messages`

So for SFT registration, `messages` is the key field we need.
